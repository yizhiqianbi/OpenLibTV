## 确定的接线冲突

## 选择、拖动与定位

源码 `3u6hjewm8qox_.js` @761–763k 的 eG 为 standalone flag 且 image subtype，eI 只在非 box-select、恰一个 selected、该 selected 为本组 direct image child 时成立。@790–794k 的 t3 为 eN 或 eG&&eI；工具栏 host 要 `!ew && t3 && !ta && !td`，eG 分支使用 ts，普通组用 GroupNodeToolbar。eN `useShouldShowGenerator` @679719–680303 判断单选、特殊 reference/mark/focus 目标及非 box-select，本身不含 drag gate；拖动隐藏由 `NonScaledWrapper hideWhenDragging=true` @678554–678917 和 `2ob2qo_b0az9v.js` module485615 的 nodeLookup.dragging 承担。source caller 的 baseOffset20 + gap8 为28 screenpx；具体 host 定位另见本批 source UI 审计，不能仅用 `selected.includes(group.id)` 替代。@767804 的 td 在 title editing 时为 true，结束后延迟200ms再解除；无 title-editing 本机状态时不能宣称这一分支已实现。

接线前 `CanvasGroupNode` toolbar 仅 `active && !readonly`；没有 selected 数量、box-select、dragging 或 title-editing gate。因此多选多个真实组时可显示多个 group bar，selected group+child 也显示 bar；只选一个本组 image child 时反而没有父组 bar。Viewport 已有 `generator.draggingNode`、`selectionRect` 和 selected 列表，须交给纯资格/helper，而不是另起 DOM 拖动监听。Pointer 的 `draggingNode` 在本机4px阈值后生效；源时序差异仍需保留。

现有真实 group bar 留在 `.cv-world` 的 group 内，`left:0; top:-48px; white-space:nowrap`，只做 `scale(1/zoom)`。它没有 board 尺寸测量、最大宽度、clamp 或横向滚动，board 又 `overflow:clip`。因此在390px board 中，右侧组的工具栏越界部分会被裁掉；靠上或负 world 坐标也会被裁。inverse scale 只保持控件大小，`top:-48px` 的屏幕距离仍随 world zoom 改变。这里只是静态确定的几何问题，本记录没有重新进行原生390px操作。

普通多选的 `CanvasSelectionToolbar` 已有 board-local anchor、8px边距、ResizeObserver、固定屏幕尺寸与横向滚动；相关测试有320px限制和390px resize夹具。其 `useSelectionToolbarAnchor` 目前是文件私有函数，可提取成小型公开定位 hook，不能把整套普通多选动作作为 standalone toolbar。新 toolbar 增加控件后仍须原生1280/390px检验，不能引用旧多选几何测试作为新 toolbar 完成证据。

## 可复用的公开 API 与 ownership

| API                                                                       | 可复用范围与限制                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `graphActions.commitGraph(next,{expectedGraph,historySnapshot?})`         | 当前公开的布尔 CAS 提交入口：documentKey/ready/readonly/active，raw nodes/edges/models identity，projectGraph 同时投影 previous/next，再复核 raw identity；同步发布 currentDocument，然后一次 history 和 React state。next 必须带当前 graph 的文档/权限字段。新 controller 应读取最新 raw graph，做纯计划，保留 edges，拒绝失败后的 selection/fit。 |
| `canvasDrafts.project(document)`                                          | 纯投影同 storageKey、匹配 prompt baseline 的 live/retained draft。Root 已注入 Graph，调用者无需第二次保存或手动拼提示词。删除后的节点不会复活；修改 child params 时保留 prompt baseline 与其余字段，不能用设置菜单打开时的完整 data 覆盖最新 params。                                                                                               |
| `canvasWorldPosition` / `canvasNodeSize`                                  | world 脱离与本机手写 renderer 尺寸协议。settings 的 source flow dimensions 与 display explicit dimensions 必须区分；源 tm measured 优先不能被全局 display adapter 偷换。                                                                                                                                                                            |
| `reconcileStoryboardGridMembership` / `resolveStoryboardGridPresentation` | 前者为 strict standalone+image+actual非空的写计划，后者只投影 slot/order/title/尺寸；二者可复用，但不能把普通组强行送入宫格 reflow，也不能对 empty source 分支猜写。                                                                                                                                                                                |
| `useAgentToolbarPopover` / `agentToolbarPosition`                         | 非 modal 菜单，fixed positioning、8px viewport clamp、上下翻转、Escape 回 trigger；外部 pointer/focus 关闭保留新焦点；共用 dialog-stack child dismissal。disabled 关闭菜单且不抢焦点。适合设置/二级菜单，不是确认 dialog。                                                                                                                          |
| `EditorDialog` / 现有 `CanvasDialogs`                                     | 确认层共用 dialog-stack、Escape/Tab/background 生命周期；不要另加 body lock。触发器被转换/清空/解组销毁后，关闭回焦点须由 request controller 定位仍存在 group 或其结果，而非盲 focus 旧 DOM。                                                                                                                                                       |
| `fitCanvasView` + Root `focusNodeView`                                    | 设置提交后读取已成功计划的实际 nodes 做 fit；源 manual grid 会在 RAF 请求 fit。迟到 RAF 须核对 request/document/current group，viewport fit 不能写入第二次 graph history。                                                                                                                                                                          |
| Pointer `cancel`                                                          | 若设置动作需要接管尚在写位置的手势，Root 可使用现有 writer 取消；不要由 toolbar 建新 pointer/global listener。普通只读查看和被隐藏控件不需要虚构额外 writer。                                                                                                                                                                                       |

`useCanvasSelectionActions.target()` 只读取最新 props 的 active/ready/readonly，没有捕获某次 group setting request 的 documentKey、group identity 或 membership。保留一个 callback 后切到新文档，再带同 groupId 调用，可以命中新文档同 ID；同步 toolbar 普通动作目前依赖当前渲染，但新的确认层、异步拼接和 RAF fit 不能继承这种假设。controller 应拥有唯一 request、捕获文档身份，在 confirm/迟到结果前复核 group 类型/资格及 source 所要求的成员/基线；不能只检查数字 ID。

现有 `change()` 已记录 previous 的草稿，但只调用 setNodes/setEdges，不像 Graph 将 next 一并投影和同步 currentDocument，且拒绝时返回 undefined。新 group 设置不应把 undefined 当确定成功，选择/通知/fit只在布尔提交成功后执行。

## 已有验证与本批待验

已读相关测试：`CanvasGroups.integration.test.jsx`（普通 group layout/run/ungroup/persist）、`CanvasGroupNode.storyboard.test.jsx`（shell/title/slots 与旧 toolbar callback）、`CanvasSelectionToolbar.test.jsx`（顺序、Escape、readonly/ready、anchor/resize/focus identity）、`useCanvasSelectionActions.test.jsx`（创建、一次 history、失败与切文档）、`NodeCanvas.storyboard-grid-create.integration.test.jsx` 与 `NodeCanvas.storyboard-drop.integration.test.jsx`（真实创建/drop/empty slot/history/返回焦点）。这些不覆盖新 standalone ratio/manual capacity overflow/convert/clear/settings UI，旧 group toolbar callback 测试需要随新 branch 的明确 source 行为更新。

本批应重点验：完整 preferred order 不因无关解组变化；group 被删/换类型/切文档后确认不落旧请求；child prompt最后150ms与同时 params修改保留；每个有 snapshot 的操作恰一次 undo/redo；group/唯一image child/多选/box-select/drag/title-editing的显隐；390px横向可达及放大缩小；菜单Escape回 trigger，外部focus关闭不抢新控件，确认层关闭后只回有效group。真实手机/Safari、真实拼接上传/费用/生成与账号资源仍不是上述静态检查或本机测试的结果。
